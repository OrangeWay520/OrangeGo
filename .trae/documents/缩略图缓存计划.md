# 缩略图持久缓存改造计划

## 目标
把图片/视频的缩略图从「运行时内存缓存」升级为「磁盘持久缓存」，使得**源文件被删除或移动后，传输记录里的缩略图依然存在**，直到该传输记录被删除/撤回/清空。设置里提供「清除缓存」入口；自动清理**不单独设时长**，跟随现有传输记录清理逻辑（记录清则缩略图随清）。

## 已确认的设计决策
- 缓存 key = **内容指纹**（`文件名 | 大小 | 修改时间` 的哈希），与源文件路径解耦，源文件删/移后缩略图仍按 key 命中。
- **单条精确回收**：删除单条记录、撤回、清空全部记录，都精确清理对应缩略图缓存。
- 撤回消息时同样清理缩略图。
- 两端都实现，逻辑对齐（协议/数据层各自本地存储，但行为一致）。

## 一、新增「缩略图磁盘缓存」模块（两端）

### Android：`ThumbCache.kt`（新文件，`com.orangeway.go.core` 或 ui 同包）
- 根目录：`context.cacheDir/thumbnails/`
- API：
  - `fun keyOf(name: String, size: Long, mtime: Long): String = sha256("$name|$size|$mtime")`（十六进制，前 32 位即可）
  - `fun resolve(context, key): File?`（存在返回 File，否则 null，检查目录内 `key.png`）
  - `fun put(context, key, bitmap): File`：把 Bitmap 编码为 PNG 写入 `key.png`，压缩质量无关紧要（缩略图）
  - `fun deleteKey(context, key)` 与 `fun deleteKeys(context, keys)`
  - `fun clearAll(context)`：清空整个 thumbnails 目录
  - `fun totalSizeBytes(context): Long`（供设置界面显示缓存大小）
- 所有操作在 IO 线程调用。

### Windows：`ThumbCache.cs`（新文件，`OrangeGO.Windows.Core`）
- 根目录：`Path.Combine(Environment.GetFolderPath(LocalApplicationData), "OrangeGO", "thumbnails")`
- 与 Android 同构：
  - `string KeyOf(name, size, mtime)`
  - `BitmapSource? Load(string key)` / `void Save(string key, BitmapSource)`（PngBitmapEncoder）
  - `void Delete(string key)` / `void Delete(IEnumerable<string>)`
  - `void ClearAll()`
  - `long TotalSizeBytes()`

## 二、内容指纹 key 的挂钩（生成时计算并存到记录）

### Android（OgoViewModel.kt / OgoApp.kt）
- `TransferItem` 增加字段：`val thumbKeys: List<String> = emptyList()`（与 localRefs 一一对应；仅在媒体生成缩略图时才有值）。
- 传输记录序列化（schedulePersist L300-305）：增加 `put("thumbKeys", JSONArray(t.thumbKeys))`；反序列化 loadTransfersFromDisk 同步读取。
- 缩略图生成处：
  - 图片 `ChatImageThumb`（OgoApp.kt ~L1778）：加载得到 Bitmap 后，用源文件元数据算 key → `ThumbCache.put`，并把 key 回写该 TransferItem。由于 TransferItem 是 data class，需经 ViewModel 的 updateTransfer 原子更新 thumbKeys。
  - 视频 `loadVideoThumb`（~L1855）：抓首帧后同样 put + 回写。
- 渲染读取：`rememberVideoThumb` / `ChatImageThumb` 先查 `ThumbCache.resolve(context, key)`，命中则显示磁盘缓存，不再重新解码源文件；源文件仍在且命中优先用缓存（更快）。

### Windows（ViewModels.cs + MainWindow.xaml.cs）
- `TransferItem` 增加 `public List<string> ThumbKeys { get; set; } = new();`（与 MediaPaths 对应）。
- DTO（ToDto/FromDto，L246-264）：序列化 ThumbKeys。
- 缩略图生成处（ShellThumbnail.LoadThumbnailAsync 调用处，MainWindow.xaml.cs）：拿到 BitmapSource 后算 key → `ThumbCache.Save`，并把 key 写入对应 TransferItem.ThumbKeys（通过 UI 线程更新，触发 PropertyChanged）。
- 渲染读取：先 `ThumbCache.Load(key)` 命中则直接显示；否则并发生成源文件缩略图并存缓存。

> 说明：两端各自生成/读取自己的缓存，不跨端共享文件（缩略图是本地 UI 资源）。

## 三、缓存清理联动（删除/撤回/清空/自动清理）

### Android（OgoViewModel.kt）
- `deleteTransfer(id)`（L315）：删除记录前取出其 `thumbKeys` → `ThumbCache.deleteKeys`。
- `clearTransfers()`（L324）：清空记录 → 顺带 `ThumbCache.clearAll()`（简单粗暴且正确：全清了）。
- `recall(id)`（L581）与 `onRecall(sendId)`（L599）：被撤回记录若之前已生成缩略图，`ThumbCache.deleteKeys` 清理。
- `pruneTransfers()`（L339）：自动清理删掉的记录，取其 thumbKeys 清理缩略图。

### Windows（ViewModels.cs / MainWindow.xaml.cs）
- 单条删除（ClearTransfer 对应点击处理）：取出 ThumbKeys → `ThumbCache.Delete`。
- 清空全部：`ThumbCache.ClearAll()`。
- `OnRecallAsync`（MainWindow.xaml.cs L2124，已改过）：被撤回记录删除缩略图缓存。注意当前 OnRecallAsync 已在删 MediaPath 文件；这里把 ThumbKeys 一并删。

## 四、设置界面「清除缓存」入口

### Android（OgoApp.kt SettingsScreen L2468~）
- 新增一行「缩略图缓存」：右侧显示当前缓存大小（`ThumbCache.totalSizeBytes`，进入设置时刷新），点击「清除」→ 确认 → `ThumbCache.clearAll()` 并刷新大小。
- 复用现有 `SettingsRow` 模板与多语言文案。

### Windows（MainWindow.xaml + 设置面板）
- 新增设置项「缩略图缓存：X MB」+「清除」按钮，点击清空缓存并刷新显示。
- 语言 key（zh.xaml 等 14 种语言）补齐。

## 六、行为确认（验收点）
- [ ] 发送/接收一张图片或视频 → 缩略图正常显示，同时缩略图已存入磁盘缓存目录。
- [ ] 删除源文件/移动源文件 → 传输记录里缩略图仍显示（命中磁盘缓存）。
- [ ] 删除单条传输记录 → 该条缩略图缓存被清（缓存大小减小）。
- [ ] 撤回一条消息 → 该条缩略图缓存被清。
- [ ] 清空全部传输记录 → 缩略图缓存目录被清空。
- [ ] 自动清理触发删旧记录 → 旧记录缩略图随之清理。
- [ ] 设置界面「缩略图缓存」显示大小，可一键清除。

## 备注
- 采用最小、可控改动，不重建现有缓存/预览架构，只叠加磁盘缓存层。
- 两端行为一致，但缓存目录各自独立，无跨端共享。
